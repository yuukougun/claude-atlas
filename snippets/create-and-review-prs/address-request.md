指摘ごとに次を書く。

1. 指摘の番号と、指摘の要約
2. 指摘が正しいかの見立てと、その根拠（コードの該当の行、または実行した結果）
3. 案：直す／直さない／人に確認する
4. 直す案なら、直す箇所と、直った後に何を実行して確かめるか

次を守る。

- 指摘に賛成することを前提にしない。根拠が見つからない指摘は、そう書く
- テスト・期待値・設定のファイルは変えない。変えないと直らないと思う場合は、直さずに理由を書いて人に確認する
- 案の表を返すところまでで止める。私が「この番号を直して」と返してから、直す
