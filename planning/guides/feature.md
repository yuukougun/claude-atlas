# 型の手引き：feature

- 版：2026-11-04 第1版（工程6a。試作〔工程7〕で確かめて確定する）
- 共通の手引き（common.md）と一緒に使う。ここには、この型の構成の目安と、この型に固有の注意だけを書く

## 1. 用途と、必ず持つもの

元：design §2.2・§3.3・§4.1

- 用途：機能の使いどころと注意点
- 冒頭の要点のほかに必ず持つもの：機能の属性のバッジ（強制力・読み込みの時期など。数値ファイルの機能の項目から道具が作る）と、`tracks`（数値ファイルの features の id。catalog が決める）
- 1機能1ページにする。密接な系統は1ページにまとめ、節（anchor）に分ける。公式のリファレンスの網羅はしない
- level を持つ

## 2. 構成の目安

元：design §6.3

- 要点（強制力・確認日と版のバッジ）→ 使いどころ（どの原因を防ぐか）→ 最小の使い方（面のタブ）→ 雛形（折りたたみ）→ 効かない場面・落とし穴 → 比べる相手 → 古くなった助言

## 3. この型に固有の注意

元：design §6.4・§3.3・§6.7・§6.9・§4.1、requirements §5.3、decisions 2026-11-03 方針 B6

- 要点に「強制力」（お願い・鍵・モデルの判定・なし）の項目を足す。値は数値ファイルの機能の項目（features の enforcement）から道具が書き、手で書かない（目印の形は、作る層とともに決める）。値の後に、何を止められて何を止められないかを一言で書く
- 機能の属性（成熟度・強制力・読み込みの時期・コンテキストのコスト・圧縮で残るか）を、本文に手で書かない。バッジと比較の表は道具が作る。本文で値に触れるときも、道具が書く形にする（形は作る層とともに決める）
- 「使いどころ」は、どの原因（`prevents`）を防ぐかから書く。機能の一覧の説明で始めない
- 「最小の使い方」は、動く最小の形だけにする。面ごとに手段が違えば面のタブにする。全オプション・全キーは公式の文書を指す
- 「雛形」の節は、共通の手引き §12 に従う（折りたたみ方は、作る層とともに決める）
- 機能が入った版と要る最低の版を、手で書かない（数値ファイルの「入った版」から道具が書く）
- 「効かない場面・落とし穴」は、確かめた事実か、根拠の印付きで書く。版で挙動が変わったものは今の挙動を書き、古い挙動は台帳に任せる
- 「比べる相手」は、比較のページ（comparison）をリンクの目印で指す。比較の表を手で作らない
- 「古くなった助言」は、front matter の `outdated_advice` の助言を台帳のページで指し、今どうするかを一言で書く。変わった時期と版は手で書かない（台帳と名称の表が持つ）
- research preview・experimental の機能のページは、概念だけの短いページか節にする。本体に入って読者がふつうに触れる機能の扱いは、共通の手引き §14 の「軽く扱う」に従う
- 用語索引で主のページ（数値ファイルの features の page）になる機能のページは、題名と別名で引かれる。題名と別名の直しは提案する（共通の手引き §21）
