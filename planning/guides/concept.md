# 型の手引き：concept

- 版：2026-11-04 第1版（工程6a。試作〔工程7〕で確かめて確定する）
- 共通の手引き（common.md）と一緒に使う。ここには、この型の構成の目安と、この型に固有の注意だけを書く

## 1. 用途と、必ず持つもの

元：design §2.2・§3.1

- 用途：なぜそうなるか（原理・仕組み）と、頼み方の技法（どう頼むと何が変わり、なぜか）
- 冒頭の要点のほかに必ず持つもの：どの原理・どの原因に関わるか。front matter の `principle`・`prevents`・`pitfalls` の値を、本文で名指して結び付ける
- level を持つ。要点の最初の項目は「何が分かるか」にする（共通の手引き §3）

## 2. 構成の目安

元：design §6.3

- 原理・仕組みのページ：要点 → 何が起きるか（例）→ なぜそうなるか（比喩付きの図）→ 何に効くか（原理・原因へ）→ 誤解 → 関連
- 技法のページ（頼み方の技法を扱うもの。主に prompting の分野で、迷ったら指示に従う）：要点 → 頼み方の例（Before/After）→ 何が変わるか → なぜ効くか → 効かない場面・やりすぎ → 関連
- 最後の「関連」は、テンプレートがページ下部に出す（共通の手引き §4）

## 3. この型に固有の注意

元：design §6.1・§6.6・§6.10・§6.11、requirements §6.2・§6.6

- 「何が起きるか」は、読者が出会う具体的な場面から入る。定義から始めない
- 「なぜそうなるか」は仕組みで説明し、比喩付きの図を使う（比喩は共通の手引き §7 の一覧）。公式の文書や研究で確かめられない内部の動きを断定しない。書くなら根拠の印（類推・推論）を付ける（共通の手引き §8）
- 「何に効くか」で、原理と原因へ結び、対処のページをリンクの目印で指す。対処の手順の本体は書かない（持ち主のページに任せる）
- 「誤解」は、実際に出会う誤解と、正しい理解・確かめ方を対にして書く。元が古くなった助言なら、台帳（front matter の `outdated_advice`）を指す
- 技法のページでは：
  - Before/After は同じ依頼で並べ、After で何を足したかを注記する（共通の手引き §7）
  - 「効かない場面・やりすぎ」を必ず書く。どこでも効く手法として書かない
  - 呪文を効く手法として教えない（共通の手引き §14）
  - 調査の間で食い違った頼み方の論点は、共通の手引き §6 の書き方にそろえる
- 動く図「コンテキストの埋まり方」は、公式の対話の図へのリンクを主にし、自作の図は公式にない点（毎回全部を読み直すこと・圧縮）だけにする。動く図にするのは、公式で足りないと試作で分かったときだけにする
