# 型の手引き：comparison

- 版：2026-11-04 第1版（工程6a。試作〔工程7〕で確かめて確定する）
- 共通の手引き（common.md）と一緒に使う。ここには、この型の構成の目安と、この型に固有の注意だけを書く

## 1. 用途と、必ず持つもの

元：design §2.2・§4.1

- 用途：似たものの使い分け
- 冒頭の要点のほかに必ず持つもの：比較の表（属性は数値ファイルから道具が作る）と判断例
- 比べるのは、混同されやすい組だけである
- level を持つ

## 2. 構成の目安

元：design §6.3

- 要点 → 比較の表（生成）→ 選び方（判断例）→ 組み合わせ方

## 3. この型に固有の注意

元：design §4.1・§7・§3.3・§5.3

- 比較の表を手で書かない。道具が `tracks` の機能の属性から、目印の間に作る（作る予定：gen_site.py --check）。目印の名前は、道具とともに確定する。表にない属性が要るなら、数値の提案に書く（共通の手引き §21）
- 比較の表の値を本文で繰り返さない（食い違うため）。本文で値に触れるときは、道具が書く形にする（機能の属性は feature の手引きのとおり、数値は共通の手引き §9 の目印）
- 手で書くのは、選び方と組み合わせ方である。選び方は判断例（共通の手引き §7）で、場面ごとにどちらを選ぶかと理由を書く
- 要点の「何ができるか」は、答えそのもの（「〜なら A、〜なら B」の形の選ぶ基準）を1文で言う。「A と B の違いを説明する」で済ませない
- 組み合わせ方は、両方を使うときの分け方（どちらに何を置くか）を書く
- 各機能の使い方の本体は、それぞれの機能のページに任せ、リンクの目印で指す
