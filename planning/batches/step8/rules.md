# 工程8：バッチの終わりの扱いの決め（先例）

バッチの担当の報告（write.md・review.md）の「メインに判断してほしいこと」と「提案」を扱うときの決め。バッチ1（2026-11-05）でメインが決めたものを、次のバッチの終わりの担当がそのまま当てる。合わないものだけをメインに上げる。

## ページで直すもの

| 件 | 扱い |
| --- | --- |
| 研究の結果（割合・件数・対象のモデルの名） | 研究の名・年・対象を添えていれば、手書きのままでよい（CLAUDE.md・common §9） |
| 増え続ける件数（GitHub の issue の件数・報告の数など） | 手で書かない。「複数の報告がある（YYYY-MM-DD の確認）」のように件数を書かない形にする |
| 今のモデルの世代名・版の範囲（「Claude 4.7 以降」など） | 手で書かない。「新しい世代のモデル」などに言い換え、要るなら数値の提案に回す |
| 根拠の印のない推論の文 | 残すなら（推論・実践例なし）などの根拠の印を付ける。要らなければ削る |
| 症状のページに入った研究の要旨・仕組みの説明 | 1〜2文に縮め、前提のページを link の目印で指す |
| 束にない知識（記憶）で書いた事実 | 一次資料を開いて確かめて直すか、削る（Web の取得は1ページ2回まで） |
| related への追加の提案 | 相手が目次にある id なら当てる |
| 本体を生成するページで、生成の目印の代わりに手で書いた表 | 生成の目印（tools/gen/config.yml の hosts）に替える |
| 図の要否 | 表や文で代えて内容が足りていれば、図は作らない |
| 書き方の検査の警告 | 下書きでは止める条件にしない。直して読みにくくなるものは残す（エラーは0にする） |

## 後でまとめて扱うもの（backlog.md に集める）

| 件 | いつ |
| --- | --- |
| 数値の提案（facts-proposal.yml・write.md の proposals） | 第一波の終わりに、1回で data に入れて目印を置く |
| 用語集に足す語 | 用語集のページ（glossary）を書くバッチで、担当に渡す |
| 道具・data の形への提案 | メインがバッチの終わりに判断する |
| 公刊版の出典など、出典の差し替え | ページを直すときに、そのページの sources.d に足す |
