claude-atlas は、Claude 全般を使いこなすための、辞書として引く日本語の教材である。読者は開発の経験がある人。リポジトリは `/home/yuuki/projects/kyopro2/claude-atlas`。今日は 2026-11-04。

工程3で23分野の目次（`planning/catalog/<field>.yaml`）ができ、工程4で4人の担当が批判的に見直した（`planning/batches/step4/review-R1〜R4.md`）。メインが指摘への対応を `planning/design-review.md` に決めた。あなたは、受け持ちの分野のファイルに、目次の直し（design-review の **DR-19** と、それに関わる DR-02・DR-17・DR-18）を反映する。分野ごとに持ち主を1人に決めてあるので、ほかの担当と同じファイルを書くことはない。

6. 必要なら：`planning/design.md` §3〜§6、`planning/catalog/registry.yaml`・`features.yaml`、ほかの分野のファイル（読むだけ）、調査資料

## 3. すること

1. DR-19 の表の各行のうち、受け持ちのページに関わるものを反映する。行の割り当ては README.md の2段目の表の「主な行」にあるが、それ以外の行でも受け持ちのページが出てくれば扱う
2. **a（言い換えの重なり）**：受け持ちの対処のページの signs に、症状のページが振り分ける困りごとの言い換えがあれば、外すか、その対処が直接の答えになる狭い場面の困りごとか、goal の形に書き換える（catalog/README §4.5 の4）。わざと1つの問いにまとめる goal は、ほかのページと同じ文にそろえてよい（逆引きで1行に束ねる。DR-15）
3. **d（別名の重なり）**：fix-aliases.md の表で、受け持ちのページが「外す側」なら、その別名を外す。そのページが扱う別の機能の公式の名前で、外すと引けなくなるものは残し、報告に書く
4. **e（前提の鎖）**：`python3 tools/check_catalog.py --field <field>` の「推移的な前提」の警告を、前提から外して消す（related に移すかは近さで決める）。delegate は R3 の付表B の辺も扱う（4本目の what-not-to-delegate → verifier-defines-problem は、前提として要るかを見て決める）
5. 検査する（§5）
6. 報告を書く（§6）

## 4. してよいこと・しないこと

- 書いてよいのは、受け持ちの分野のファイルと、自分の報告（`planning/batches/step4/fix-<担当>.md`）だけ。registry・features・設計書・design-review・ほかの分野のファイルは変えない
- **ページの id と、sections の anchor を変えない**。anchor を足すのはよい
- **ページをまとめてよいのは、DR-19 の表が名指しするもの（i・p・q）だけ**。まとめたら `merged` に `{id, into, reason}` を書く（ほかの分野からの参照は、メインが後で道具で直す）。q は「独自の判断を notes に1行で書けないなら」まとめる。書けるなら残し、その1行を notes に書く
- **新しいページは b（症状辞典）と g（api）だけ**。notes に「新規（2026-11-04 工程4）：理由」と書く
- `priority`・`level` を変えるのは、DR-19 が求め（f・i・x）、規則（必須のページの前提は必須、前提に上の段を置かない）が保たれるときだけ。ほかの分野のページの優先度を上げないと規則が保てないときは、変えずに報告の「メインへ」に書く
- `wave` を変えない（b の新しい症状のページには、ほかの症状のページと同じく `wave: 1` を付ける）
- 変えたページの notes の末尾に「（2026-11-04 工程4：DR-19 <記号>）」を足す
- 調査資料の訂正・注記の付いた主張（`【2026-11-03 訂正】`・`【2026-11-03 注記】`）を、summary・signs・題名の根拠にしない
- summary・signs・title に、変わりやすい値（数値・既定値・料金・モデルの世代とモデルの系統の名前・上限）を書かない
- 第三者を否定的な文脈で名指ししない（materials と notes にも、個人の名前を書かない）
- git の操作をしない（読むだけのものも使わない）。Web を開かない
- 検査の道具（check_catalog.py）は、別の担当が同時に `routes` の検査を足している。道具が途中で動かないときは、少し置いてから流し直す

## 5. 検査

受け持ちの分野ごとに `python3 tools/check_catalog.py --field <field>` を走らせ、エラーを0にする。まとめたページ（merged）を指す、ほかの分野のファイルの参照のエラーは、メインが後で直すので残ってよい（報告に件数を書く）。推移的な前提の警告は0にする。ほかの警告は、理由を notes に書けば残してよい。

## 6. 報告の形（`planning/batches/step4/fix-<担当>.md`）

1. DR-19 の行ごとの扱い（表：記号｜変えたページ｜中身｜しなかったときの理由）
2. 言い換えの重なり（a）で直した sign（前 → 後）
3. 別名の重なり（d）で外した別名と、残した別名の理由
4. 外した前提（e）
5. まとめたページ・新しいページ・priority と level を変えたページと理由
6. メインへ（ほかの分野に関わる直し、決めきれなかった点）
7. 検査の結果（エラー・警告の数と、残した警告の理由）
8. 確かめていないこと

最後の返答（メインへの報告）は300字まで。
