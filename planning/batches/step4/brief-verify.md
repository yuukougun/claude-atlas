# 工程4：反映を確かめる担当への共通の指示

- 版：2026-11-04 v1

## 1. 背景

claude-atlas は、Claude 全般を使いこなすための、辞書として引く日本語の教材である。リポジトリは `/home/yuuki/projects/kyopro2/claude-atlas`。今日は 2026-11-04。

工程4で、4人の担当が設計書と目次を批判的に見直し（`planning/batches/step4/review-R1〜R4.md`）、メインが対応を `planning/design-review.md` に決めた（DR-01〜DR-20 と §6）。その対応を、設計書は担当 D1 とメインが、検査の道具は T3 が、目次は分野ごとの担当 F1〜F7 とメインが反映した（報告は `planning/batches/step4/fix-*.md`）。

あなたの仕事は、**反映が決定どおりかを、書いた担当とは別の目で確かめる**ことである。書いた担当の報告を、そのまま正しいと受け取らない。報告に「直した」とあっても、ファイルで確かめる。

## 2. 守ること

- 書いてよいのは自分の報告（`planning/batches/step4/verify-<担当>.md`）だけ。ほかのファイルは読むだけにする
- git の操作をしない（読むだけのものも使わない）。Web を開かない。`../kyopro-atlas` は読まない
- 第三者を否定的な文脈で名指ししない
- 決定（design-review）そのものの良し悪しは見ない。決定どおりに反映されたか、反映で新しい食い違いや誤りが生まれていないかを見る。決定の中の食い違いに気づいたら、別の節に分けて書く

## 3. 報告の形（`planning/batches/step4/verify-<担当>.md`）

1. 見た範囲と方法（読んだもの、道具で数えた方法）
2. 指摘の一覧（表：番号｜重さ〔直す・直したほうがよい・軽い〕｜場所｜問題｜根拠〔決定の番号と、ファイルの該当の箇所〕｜直し方の案）。「直す」は、決定に反する・決定が反映されていない・反映で誤りが入ったもの
3. 決定どおりと確かめたもの（短く。DR の番号で）
4. 決定の中の食い違い（あれば）
5. 確かめていないこと

最後の返答（メインへの報告）は300字まで。重さごとの件数を書く。
