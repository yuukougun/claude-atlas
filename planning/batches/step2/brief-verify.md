# 工程2：資料への反映を確かめる担当への共通の指示

- 版：2026-11-03 v1
- 反映した担当（W-A〜W-D）とは別の担当が確かめる（書いた本人に採点させない）

## 1. 背景

工程2の担当（R1〜R7）が一次資料で確かめた結果（`planning/research/22〜28`）を、別の担当（W-A〜W-D）が調査資料と `planning/requirements.md` に反映した。決まりは `planning/batches/step2/brief-apply.md` §2〜§3 と、`planning/decisions.md` の 2026-11-03「工程2（調査の補完）の結果への回答」にある。資料は、この後 GitHub の公開のリポジトリに入る。

反映の変更は、まだ commit していない。`git diff -- <ファイル>` で、反映の前（HEAD）との差分が見られる。反映した担当の報告は `planning/batches/step2/apply-W-*.md`。

## 2. 確かめること

1. **人物・団体の訂正**：直した文が、報告（特に research/24・25）の「正しい内容」と出典に合っているか。新しく確かめていない主張が足されていないか。`【2026-11-03 訂正】` の注記があるか
2. **否定的な文脈の実名**：差分だけでなく、担当のファイルの全体を見て、否定的な文脈（古い助言の例・批判のコメント・失敗例・低い評価・誤りの指摘）に、個人の名前（ハンドルを含む）や、その記事・投稿の URL が残っていないか。肯定的・中立の文脈の実名と URL が、外されすぎていないか
3. **注記**：誤りの箇所の直後（表なら表の直後）に置かれているか。表の行の間に挟まって、表が割れていないか。指している報告の番号（research/2N の #M）が実在し、注記の内容が報告と合っているか
4. **漏れ**：報告が担当のファイルの場所を挙げて「誤り」「一部誤り」「確かめられない」とした項目のうち、反映されていないもの
5. **関係のない変更**：誤りに関係のない文の言い換え、見出し・節の番号・表の形の変更、Markdown の崩れ

## 3. 守ること

- 読むだけにする。担当のファイルを直さない。git は読む操作（`git diff`・`git log`・`git show`）だけにする
- Web を開かない（報告と、報告の出典の記録で確かめる）
- 書いてよいのは、自分の報告（`planning/batches/step2/verify-<担当>.md`）だけ

## 4. 報告の形（`planning/batches/step2/verify-<担当>.md`）

1. 確かめた範囲（ファイル、差分の行数、読んだ報告）
2. 指摘の一覧：表で、1件1行。列は「#・ファイルと行・種類（訂正・実名・注記・漏れ・関係のない変更）・内容・直し方の案・重さ（必須／推奨）」
3. 問題がなかった点の要約
4. 確かめていないこと

最後の返答（メインへの報告）は300字まで。
