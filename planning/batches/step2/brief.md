## 1. 背景

claude-atlas は、Claude 全般（claude.ai アプリ・Claude Code・モデルと effort・頼み方・API と SDK の概念・安全とデータ・組織での運用）を使いこなすための、辞書として引く日本語の教材である。読者は開発の経験（git・ターミナル・プログラミング）がある人で、公開のリポジトリと GitHub Pages で不特定多数に向けて作る。リポジトリは `/home/yuuki/projects/kyopro2/claude-atlas`。今日は 2026-11-03。

調査資料（`planning/research/00`〜`11`）は AI が書いたもので、2026-10-29 時点の確認に基づく。誤りの疑いと空白が分かっている（`planning/requirements.md` §10、`planning/research/21-step1-findings.md` §2）。工程2では、これを一次資料で確かめて直し、空白を埋め、10-29 以降の変更を確かめる。結果は、この後の設計と、ページの執筆と検証の材料になる。

## 3. 確かめ方

- **一次資料を根拠にする**：公式文書（code.claude.com・platform.claude.com・support.claude.com など）、公式ブログ、CHANGELOG・リリースノート、論文や記事の原文。二次情報（まとめ記事・報道）は、一次資料を探す手がかりにだけ使う。一次資料が見つからないときは、二次情報だけだと明記する
- **AI の利用を断るサイトを資料にしない**：新しいドメインを読む前に `python3 -I tools/check_noai.py <URL>`（リポジトリの根で実行）で確かめ、結果を報告に書く。noai・noimageai の指定があれば読まない。**atcoder.jp と codeforces.com（サブドメインを含む）は開かない**（WebFetch・curl・ブラウザのどれでも）
- **確認日と版を書く**：事実ごとに確認日（2026-11-03 など）を書き、版に依存するもの（Claude Code の版・モデル名・プラン）は版も書く
- **推測で埋めない**：確かめられなかったものは「確かめられない」とし、何を試したかを書く
- **書き方**：他者の文章を写さず、自分の言葉で要約する（引用は短くし、出典を添える）。報告は だ・である調の日本語
- **Web 検索の枠**：検索の回数には限りがある。URL が予測できる公式文書は、検索せずに直接読む

## 4. 守ること

- 書いてよいのは、割り当てられた報告のファイル（`planning/research/2N-*.md`）だけ。ほかのファイル（調査資料・requirements・decisions など）は変えない。直したいことは報告に「提案」として書く（メインがまとめて反映する）
- git の操作（commit・push など）をしない
- `claude -p` などで Claude Code を実際に動かす確認はしない（使用量を使い、作者の設定が混ざるため。工程2では文書で確かめる）。`claude --version`・`claude --help` は使ってよい
- 実在の人物・団体について書くときは、一次資料で確かめたことだけを書く

## 5. 報告の形

割り当てられたファイルに、次の節で書く。

1. **調べた範囲と方法**：確認日、使った一次資料の一覧、AI の利用を断る指定の確認の結果（ドメインごと）
2. **結果の一覧**：表で、1件1行。列は「#・主張とその場所（ファイルと節）・結果（正しい／誤り／一部誤り／確かめられない）・正しい内容（一次資料に基づく、自分の言葉で）・出典（URL と確認日）・教材への影響（関わるページ・分野・決定）」
3. **新しく分かったこと**：割り当てで求められた空白の答えや、調べる中で見つかった重要な事実
4. **提案**：調査資料・requirements・decisions への直しの提案（ファイル・場所・直した文）
5. **確かめていないこと**：判断に迷ったが確かめていない点、読めなかった資料
6. **使った量の目安**：道具の呼び出し、Web の取得と検索の回数、かかった時間

最後の返答（メインへの報告）は短くする（500字まで）：書いたファイル、件数（正しい・誤り・確かめられない）、メインに判断してほしい点。
