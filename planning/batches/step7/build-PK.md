## 2. 使い方

```
uv run python tools/make_packet.py <id> [<id> …]      そのページの束
uv run python tools/make_packet.py --wave1            第一波の全ページ（136。tools/check_catalog.py と同じ閉包）
uv run python tools/make_packet.py --all              全ページ（357）
        --out DIR（既定 state/packets）  --stats  --item-limit N（既定 3000）  --packet-limit N（既定 60000）  --root DIR（試験用）
```

- `--stats` は束ごとに文字数と、節ごとの文字数（1 ページ／2 つながるページ／3 目次／4 data／5 出典／6 材料／7 書き方）、材料の項目の内訳（見つかった・一部・見つからない・対象外・切った写し）を出す
- 束が `--packet-limit` を超えるときは、材料の抜き出しの1項目の上限を 0.7 倍ずつ（下限 600 字）下げて作り直し、`--stats` に「上限を 3000 字から N 字に下げた」と出す。下限でも超えるときは「N 字を超えている」と出す
- 終了コード：0＝作り終えた、1＝id のページがない（ほかの束は作る）、2＝読めない（site.yml がない・書き先を作れない・引数がない）
- 同じ入力から同じ束ができる（日時などは入れない）。中身が同じなら書き直さない。`--all` は 3.3 秒

## 3. 束の中身（節の番号は固定）

2. **つながるページ**：prerequisites・routes（cause ごと）・related の先の id（型と分野つき）・題名・要約。`id#anchor` は節の題も添え、sections にない anchor とページがないものはそう書く
3. **目次の情報**：templates・visual・notes・materials の一覧
4. **data**：tracks の機能（features。`match_terms` は道具だけが使うので省いた）・outdated_advice の台帳の行・それに関わる names（tracks の機能の feature と、台帳の行の `name`）。ないものは「…にない」と書く
5. **出典の一覧**：wave1-sources.yml のそのページの sources を `id｜種類｜題名｜URL` で。ページがなければ「一覧なし（…）」。data/sources.yml にない id と、AI の利用を断るドメインの出典には印を付ける
6. **材料の抜き出し**：materials の項目ごとに `### 6.N <項目>`。写しはバッククォート4つ以上の囲みに入れ、出典（ファイルと行の範囲・見出しの道筋）を添える。切ったときは「全 N 字のうち M 字を写した」と書き、中に「…（略）」を入れる

## 4. 印のたどり方（材料の抜き出し）

- ファイル：頭の数字（`00`・`research/23`・`11b` など）で `planning/research/<数字>-*.md`。`p12#N`・`p34#N`・`p56#N` は 11a・11b・11c の論点の一覧の N 行（表が複数あるときは最初の表）。頭が資料でない項目（`kyopro-atlas の…`・`registry の…`・`R1-12`・`書く前に確かめる一次資料…`）は「対象外：<項目>（理由。束に写さない）」
- 印：`§3`・`§3.1`・`§1-5`、`分野08`・`第10章`・`第1節`・`付録A-6`、`Q8`・`KQ4`・`F6`・`T1`・`E`・`D-2`・`0-4`・`A-14`・`P-4`・`(b)`、`#45`・`p56#11`、`「…」`や語、`の4`（番号つきの箇条。なければ表の4行目）、`C-1〜C-12`・`#1〜#8`・`p12#71〜p12#74`・`§9.2〜§9.5` の範囲、`と §3` で別の組。見出し・太字の見出し・表の1列目・箇条の頭の印・見出しの文字に当てる（全角と半角・引用符の違いは見ない）
- 絞り込み：前の印で範囲を絞って後の印を探す（`11 第1節 分野01 p56#11`）。単独の印は前の組の絞り込みを引き継ぐ（`03 Q4 T1・T2`）。絞った所になければファイル全体を探す。番号（の4）は絞った所の中だけ数える
- 写す所：見出しの節（次の同じ深さの見出しまで）・太字の見出しの段落（次の太字の見出しまで）・表の行（見出しつき。同じ表の行は1つにまとめる）・箇条。同じ所は二度写さず、6.N に写したと書く
- （…）の注は印に数えない。使うのは、同じ語の見出しが複数あるときの絞り込み（`書き方の方針（安全・面・表現）4`）、語で見つからないとき注が行の題そのものならその行（`対立点の表（長い作業の続け方）`）、切るときに残す段落を選ぶ手がかりの語、注に「注記」「訂正」があれば表の後の注記を添えること
- 印のある所：【2026-11-03 訂正】【2026-11-03 注記】は印ごと写す。表の後の注記は、写した行に触れているものを添える（「注記つき」で注記が3つ以下なら全部）。切るときも、表の見出し・見出し・印の付いた段落と行は残し（長いものは印から残す）、注の手がかりの語を含む段落と行を先に残す。注記が直す直前の段落も、手がかりに当たれば添える
- 見つからないとき：`見つからない：<項目>（理由）`。一部だけ見つかったときは、見つかった所を写したうえで同じ行を付ける。語の印（「冒頭」「本文」以外の語）が見つからず、手前で絞れた所があるときは、その所を写して「手前の『…』の所を写した」と書く。「本文」「注記」「表の最後の行」のように手前の所のどこかを言うだけの語は、手前の所を写すだけで見つからないとは書かない

## 8. メインに判断してほしいこと・提案

1. **対象外の扱い**：手本（`../kyopro-atlas` の docs）の項目は写さない既定にした（「構成をまねない」と添えた手本で、別のリポジトリの資料なので）。手本の先頭だけでも束に写すなら、道具に足す
2. **上限の既定**（1項目 3000 字・束 6万字）：10ページの束は 15,026〜33,604 字で、6万字には遠い。使用量を抑えるなら `--item-limit` を下げる（10ページで、1500 字なら 14,329〜28,039 字、2000 字なら 14,768〜30,169 字、4000 字なら 15,026〜36,390 字）。材料の抜き出し以外の節と束の頭が 4,574〜15,980 字あるので、上限を下げても束はあまり縮まない
3. **ワークフロー**：最初の段で `uv run python tools/make_packet.py <10ページの id>`（または `--wave1`）を流す。目次・data・調査資料を直したら作り直す（束は道具が作るので手で直さない。束の先頭にそう書いた）。`brief-page.md` §2 の「束にないことが要るとき」の判断の目安に、束の「見つからない：」と「対象外：」の行を挙げると、執筆の担当が開く資料が絞れる
4. **手引き**：`planning/guides/common.md` 冒頭の「一緒に渡すもの」の行に「材料の束（`state/packets/<id>.md`）」を足すと、手引きとワークフローの指示がそろう
5. **目次の materials の言い回し**（道具では写せない・あいまいな項目）：`00 §6 の末尾`・`00 §1 の段落`・`10 第2章 表の最後の行`・`10 第24章 実践②③`・`10 第21章 実践④`・`decisions 2026-11-03 の方針 B1`・`01（interactive-mode…）` は、節や行の印に直すと正確に写せる（今は手前の節の先頭を写している）。`00 §3 分野06「指示の置き場所」の行とその注記` のような「の行」「の本文」は問題ない
6. **lib への提案**（`tools/lib/` は直していない）：(a) `Atlas.ordered()` は docs/ と stubs/ に同じ id があると重ねて返す。束の道具は `by_id.get(id) is page` で除いた（重ならない版があれば使える）。(b) 第一波の閉包が `check_catalog.py` と `make_packet.first_wave_ids` の2か所にある。`check_catalog.py` が退くときは `lib/graph.py` に移す（それまで試験が両者の一致を見る）

## 9. 確かめていないこと

- 写しが「執筆に要る箇所か」を測る機械の指標はない。10ページの82項目と、目次全体からの無作為の 135 項目（種 3・11・21）を目で見た。それ以外の項目が正しい箇所を写しているかは、全部は見ていない（見つかった 1,858 項目は、印と見出しの文字・番号が合うことまでを道具が保証する）
- 執筆の担当が束だけで書けるか、束が長すぎないか（トークン数は測っていない）は、試作の執筆で測る
- 手がかりの語（注から取る）は粗い。漢字・カタカナの連なりと英数字だけを取り、意味は見ていない。当たらないときは頭から詰める
- 括弧が半角の項目（`(b)`・`(a)` の形4件）は、ラベルとして当たることを確かめたが、一般の半角の括弧の注は扱っていない。setext 形式の見出し（下線の見出し）は読まない
- 調査資料と計画の資料が執筆中に変わっても、束は古いまま（作り直しで直る）
