# 分かりやすさのチェックリスト

- 版：2026-11-04 第1版（工程6a。試作〔工程7〕で確かめて確定する）
- 検証の共通の決まり（common.md）と一緒に使う。照らす規則は、共通の手引きの §1・§3〜§8・§13 と型の手引き
- 渡されるもの：ページ、前提のページ
- **読者の立場**：Claude や Claude Code をかなり使っているが使いこなせていない、開発の経験がある人。前提のページは読んでいるが、このページの話は知らない
- **読み方**：3回読む。(1) 困りごとかやりたいことで引いた人として冒頭だけ、(2) 学ぶ人として全部、(3) 読者の AI が断片で読むつもりで、節を1つずつ取り出して
- 事実の正しさと出典は、この検証では確かめない（事実の検証の担当は置かない。decisions 2026-11-04）。ここでは、この読者が用を足せるか、分かるかを見る。分かりにくさの指摘には、どこで何が分からなくなったかを読者の言葉で書く

## U1 冒頭だけで用が足りるか

元：design §6.1・§6.4

- **確かめ方**：要点と導入だけを読み、signs の困りごと・やりたいことで来た読者が、このページが答えか、次に何をすればよいかを判断できるかを試す。「いつ引くか」が読者の言葉か。feature では強制力（お願いか鍵か）が分かるか
- **よくある失敗**：要点が機能の説明だけで、何をすればよいかがない。「何ができるか」と summary が違う（本文を書くうちに要点だけ変わった）。導入が歴史や一般論から始まる

## U2 判断があるか

元：design §6.1・§3.1

- **確かめ方**：なぜうまくいかないか、どこまで任せるか、どう確かめるか、効かない場面が書かれているか。任せる幅を広げる話の前に、守り（確かめる・縛る）が示されているか
- **よくある失敗**：機能の紹介と手順で終わる。「場合による」で終わり、どの場合にどうするかがない

## U3 断片で読んで通じるか

元：design §6.1

- **確かめ方**：`##` の節を1つだけ取り出して読み、何の話か分かるか。「上の」「前述の」「この方法」が指すものが、節の中にあるか。図が描かれなくても、前後の文章で要点が分かるか
- **よくある失敗**：「この方法では」で始まる節。節の中で定義のない用語。図がないと分からない説明

## U4 薄い節

元：design §6.1

- **確かめ方**：各節を消したら失われる情報があるか。型の目安を埋めるためだけの節、1〜2文の一般論だけの節、ほかのページの繰り返しがないか
- **よくある失敗**：「落とし穴」が「注意しよう」の1行だけ。中身のない「まとめ」

## U5 飛躍と前提

元：design §1.1・§6.2

- **確かめ方**：前提のページだけを知る読者として、1文ずつ前の文から出るかを見る。定義の前に用語を使っていないか。前提にない知識を当然としていないか。逆に、開発の経験（git・ターミナル・プログラミングの基本）を説明しすぎていないか

## U6 型の目安と、必ず持つもの

元：design §2.2・§6.3

- **確かめ方**：型の手引きの §1 の「必ず持つもの」があるか。目安と違う並びなら、内容から見て理由があるか

## U7 面のタブとプラン

元：design §6.5

- **確かめ方**：面ごとに手段が違う話がタブで並び、タブが `surfaces` と合うか（検査：check_pages.py「タブの面」）。面に固有の操作の詳細が、面の分野のページに任されているか。本文がプランに中立か

## U8 見せ方

元：design §6.10、requirements §6.6

- **確かめ方**：Before/After に、何を足したかの注記があるか。判断例が4行（状況・迷う候補・選んだもの・理由）で、答えが伏せられていないか、迷う候補がどちらも筋の通るものか。検証ノートに日付・版・試した場所があり、「観察」と「傾向」が分けてあるか。演習や確認問題がないか

## U9 読みやすさと用語

元：design §6.2

- **確かめ方**：だ・である調か、1文が短いか、1段落に1つの主張か（検査：textlint）。表がスマホで横に広すぎないか。用語が用語集とそろうか（検査：textlint）。独自の用語に公式の用語が併記されているか
- **よくある失敗**：1文に条件が3つ以上入る。同じことを言い換えて繰り返す。公式で表記が割れている3語を、日本語の訳で本文に書く

## U10 段階に合った絞り方

元：design §3.1、requirements §3.3

- **確かめ方**：ページの level の読者に合うか。「使う」のページが短く絞られているか。上の段の内容が、上の段のページへのリンクで済まされているか
