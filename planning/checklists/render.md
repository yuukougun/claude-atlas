# 図と描画のチェックリスト

- 版：2026-11-04 第1版（工程6a。試作〔工程7〕で確かめて確定する）
- 検証の共通の決まり（common.md）と一緒に使う。照らす規則は、共通の手引きの §3・§4・§10・§13 と型の手引き
- 渡されるもの：ページ、`docs/img/<id>/` の図、描画の検査の結果（作る予定：render_pages.py）。描画の検査は、ヘッドレスの Chrome で幅 390px のライトとダークを見る
- 手元の Chrome と日本語のフォントは、土台作りで決めて記録したもの（CI と同じ）を使う。見た環境（ブラウザの版・幅・ライトとダーク）を報告に書く

## G1 崩れ

元：design §8.6・§1.2

- **確かめ方**：幅 390px のライトとダークで、横ずれ・はみ出し・重なりがないか。表・コード・長い英数字の語が横にはみ出していないか。JS のエラーがないか（作る予定：render_pages.py）。ビルドの警告がないか（検査：mkdocs build --strict）
- **よくある失敗**：Markdown だけを読んで描画を見ない。表の列が多く、行き先のリンクが横に送らないと見えない

## G2 ページの部品

元：design §8.5・§6.4

- **確かめ方**：バッジの列（レベル・原理・成熟度・変わりやすさ・確認日と版。feature は強制力も）が出るか。draft のページに「下書き・未検証」の帯と、確認日のバッジの「未検証」が出るか。要点の囲み・別名の行・導入の順か。面のタブが切り替わり、折りたたみが開くか。ページ下部（前提・次に読む・関連・段階と更新日・誤りの報告）が出て、未公開のページが「題名（準備中）」の平文か。冒頭とフッターの非公式の文が出るか

## G3 目印とリンク

元：design §8.4

- **確かめ方**：目印の中身が描かれているか（空の目印だけが残っていないか）。リンクの目印が、公開のページならリンク、未公開のページなら「題名（準備中）」の平文になっているか。リンクが切れていないか（作る予定：check_pages.py「未公開のページへのリンク」）（検査：mkdocs build --strict）

## G4 静的な図（SVG）

元：design §6.10・§8.5

- **確かめ方**：画像にして目で見る（SVG のソースを読むだけで済ませない）。文字の重なり・はみ出し・矢印の向きを見る。ダークで読めるか（背景が塗られているか）。幅 390px で文字が読める大きさか。代替テキストが図の要点を言うか（作る予定：check_svg.py）
- **よくある失敗**：背景が透明で、ダークで文字が読めない。横に広い1枚の図で、スマホでは文字が小さすぎる。色だけで区別している

## G5 Mermaid と動く図

元：design §8.5・§6.10

- **確かめ方**：Mermaid が、サイトに置いた写しで描かれているか。ライトとダークで読めるか。動く図は、JS のエラーがなく、別のページへ移って戻っても1つだけ正しく出るか、スマホで操作できるか

## G6 図の内容

元：design §6.10、requirements §6.6、catalog/README §4.7

- **確かめ方**：図が本文の主張（仕組み・判断）を示しているか。図の値とラベルが本文と一致するか。比喩が一覧とそろうか（共通の手引き §7）。catalog の `visual` の text を満たすか。図の前後の文章だけで要点が分かるか。Anthropic のロゴと意匠をまねていないか
- **よくある失敗**：飾りの図で、主張を示していない。図と本文で例が違う

## G7 外から読まない

元：design §8.5

- **確かめ方**：フォント・Mermaid・画像・スクリプトを、外のサイトから読んでいないか（ブラウザの通信を見る）（作る予定：render_pages.py）
