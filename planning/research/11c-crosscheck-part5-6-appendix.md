### 調べる途中で分かった、MAIN への副次的な修正点

- 分野07「output style」：現在の組み込みスタイルは **Proactive・Concise・Explanatory・Learning の4種**である。MAIN は Explanatory と Learning しか挙げていない。`/output-style <style>` コマンドは v2.1.269 以降で使え、設定の `outputStyle` は大文字と小文字を区別する。
- 分野10「Stop hook で終わらせない」：MAIN の「連続ブロックには上限がある」は、**ツール呼び出しを挟まずに8回続けてブロックすると上書きされる**、と具体的に書ける。上限は `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` で変えられ、対策として `stop_hook_active` を確かめる方法がある。
- 分野10「権限ルール」：`Write(path)`・`NotebookEdit(path)`・`Glob(path)` のルールは**受け付けられるが、どこにも当てはまらない**。パスで縛るときは Edit と Read で書く。直感に反する既定なので、MAIN の方針どおり本文に書くべきである。また、Read の deny は同じパスへの Edit と Write も止める（v2.1.228 以降）。
- 分野12「/goal」：/goal の評価器はツールを呼ばず、会話だけで判定する。進捗のないまま何ターンも答え続けると、ループが止まる。

## 4. コンテストに固有の論点と、エージェント一般に通じる論点

第5部（第19〜21章）の論点は、ほとんどがコンテストに限らず使える。迎合させない聞き方（好みを伏せる、並べて比べる、推論を見せずに批評させる、批評は網羅させて採否は人が決める）、「同意は根拠に数えない」、撤退基準を事前に登録して判定者を分けること、AI の撤退の勧めにも続行の勧めにもそのまま従わないこと、中核と周辺の線引き、3行説明というゲート、技能形成の研究、がそれに当たる。これらは MAIN の背骨に欠けていた「人の側」の比例則として、新20 にまとめる価値が最も高い。第6部のうち、チーム運用（AI の承認を人の承認に数えない、リスク段階別の承認、ADR と書面のアップデート、独立に案を出してから突き合わせる、CLAUDE.md の変更を承認制にする）と振り返り（AI は集計係にとどめる、ポストモーテムで仕組みに戻す、プレモーテムの誤引用を訂正する）も、そのまま分野17や新20へ一般化できる。付録Aのうち、差分テスト、評価器の red/green テスト、実験台帳、「良すぎる結果を疑う」、分母を固定した報告、観察と提案を分ける分析、/goal の条件の書き方は、業務のエージェント運用でも有効な汎用の型である。反対に、コンテストに固有なのは次のものである。第23章の本番のタイムライン（前日、開始1時間、終盤の凍結、flag の検証、誤答のペナルティ）、AI 禁止の大会に向けた練習、AtCoder の部門の使い分け、Psyho・Shun_PI・Kiri8128 の戦術、Battlecode の事後報告、ロックボックスでの勝率、先後の入れ替え、差分スコアの assert、iter/sec、上位解法の要約、第25章の数か月のカリキュラム。これらは新21 に隔離し、本体の分野からはリンクだけにするのがよい。中間に当たるのが「AI なしでも最低限を出せる状態を保つ」「障害や上限への備え」で、業務向けには分野14の新ページ「AI が使えないときの備え」として一般化できる。
