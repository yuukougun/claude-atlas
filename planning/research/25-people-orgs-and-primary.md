### 3.3 Claude Code チームのレビュー運用の原文（requirements §10.4、P4）

**一次資料**：claude.dev Blog の「How the Claude Code team does code review」（Engineering、2026-10-15、Addy Osmani・Morgan Westlee Lunt・Qing Wang）。S4。claude.dev は、Anthropic の claude.com の記事が「Developer blog」としてリンクし、claude.dev の記事を「our guide」と呼んでいるので、Anthropic の開発者向けのブログと言える（S5）。

**原文の要点**（自分の言葉で）：

- 変更をリスクで三段に分ける。低（文書・文言・社内だけの機能・フラグの裏の追加）は、自動のレビューとセキュリティの確認が通れば人の承認なし。中（ふつうの製品の変更と、キャッシュ・自動更新・システムプロンプトなど敏感な所）は1人。高（最も危ない所と、常に2人が要るパス）は2人

- 人が持つのは、作るかどうかの判断、危ない所のレビュー、設計のレビュー、証拠を読むこと、結果に責任を持つこと
