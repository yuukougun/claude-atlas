### 書き方の方針（第三者・根拠・コンテスト）

ユーザーが7つとも承認した。

1. **第三者を否定的に扱うとき**：失敗例・古い助言・評価で、実在の個人や著作を名指ししない。助言の文言・時期・撤回の一次資料で書く。本人の振り返りは本人の言葉として紹介し、順位などは「自己申告」と添え、評価の語を使わない（D12・D13 を補う）
2. **既存の書籍・講座**：出典に挙げるだけにし、評価や推薦はしない。公式の教材（Academy・docs）は案内する
3. **推論の印**：研究も実践例もない推論・独自の提案には「推論（実践例なし）」と付け、必須ページの中心にしない（requirements §6.2 の印に足す）
4. **大会の規則**：版・確認日・類型（禁止・部門分け・許可と開示）・一次資料へのリンクだけを数値ファイルに持つ。条文の要約は載せず、一次資料で確かめていない値は下書きでも出さない（D6 と D11 の読みの食い違いを、この形で解く）
5. **kyopro-atlas との境界**：競技の練習法と AtCoder の規則の細部は kyopro-atlas へリンクし、claude-atlas は AI への渡し方と確かめ方に絞る
6. **注釈付きのセッション記録**：制作の環境と制作の記録だけから作る。再構成したものはそう書く。作者の手元の記録は使わない
7. **モデル別の公式の指針**：本文には「既定から始めて測る」と症状・対処を書き、モデルごとの値は確認日付きで数値ファイルに置く（公式同士の食い違いも並べる）

### 書き方の方針（安全・面・表現）

ユーザーが7つとも承認した。2 は 2026-11-03「公開する段階」の例外、7 は公開の約束である。

1. **攻撃の手口**：型と仕組みまで書き、送信・削除・秘密の読み取りを伴わない無害な再現だけを載せる。回避の手順と、AI を禁じる課題の隠し指示を外す方法は書かない。文書にない回避方法を見つけたら、公開より先に Anthropic に報告する
2. **安全の雛形**：安全とデータの雛形は、動作確認を通ってから載せる。読者が写して使う部分だけを止め、本文は下書きで出す
3. **断られたときの頼み直し**：誤って断られた正当な依頼に、目的と文脈を足す方法だけを書く。利用ポリシーを回避する頼み方は書かない（requirements §6.3 の「書かない」に足す）
4. **「AI 臭さ」**：読みやすさの品質として扱う。AI が書いたと分からなくする方法は書かない
5. **プランと面**：本文はプランに中立に書き、プランごとの差は数値ファイルの表に置く。Claude Code は WSL・Linux の CLI を基準にし、ほかの OS と IDE の拡張は「未確認」と書く
6. **beta と、本体に入った周辺の機能**：読者がふつうに触れるもの（会話の中の Design・Docs、検証に使う Claude in Chrome など）だけ使い方まで書き、ほかは概念と一覧にする（D15 の解釈）
7. **注意書き**：サイトに「安全を保証するものではない」「法的な助言ではない」と書く
