## 2026-11-03 形式と運用の質問への回答

[format-and-operations.md](format-and-operations.md)（v1）の §5 の7点への回答。

| 項目 | 決定 | 補足 |
| --- | --- | --- |
| ワークフロー | 制作でワークフロー（多数のサブエージェントをまとめて動かす仕組み）を使う。最初から大きな規模（kyopro-atlas と同じく同時に16〜20体まで）で回す | ユーザーの選択（推奨は「試作は既定の規模で測ってから決める」だった）。既定の規模の目安（1回10体未満）を超えるので、制作に入る前にユーザーが /config の Dynamic workflow size を変える。利用上限で一斉に止まりやすいので、再開の決まり（format-and-operations F15）を先に作る |
| hooks と permissions | 制作の規則の一部を hooks と permissions で縛り、リポジトリの `.claude/settings.json` に入れて効かせる | ユーザーの選択と注意：「過去に入れた縛りによって柔軟な対応が出来ず不適切な対処をすることも多いからそれを気をつけて」。縛る規則は少なく絞り、止めるときは理由と代わりの手段を返し、止めた記録をバッチの終わりに見直す（F19）。読者がリポジトリを開いたときにも動くことを README に書く |
| commit と push | GitHub のリポジトリを作った後は、メインが一人で直列に進める間は main に直接 commit・push し、作業ツリーで並列に直すようになったら、グループごとのブランチと pull request にする | ユーザーの選択。リポジトリを作るのは、ユーザーが言ってから |
| 公開する段階 | 下書き（draft）以降のページを、段階の印付きで公開する。骨格（stub）は公開しない | ユーザーの選択（推奨は「検証を通ったページだけ」だった）。公開の約束・方針・ライセンスに関わる文は、下書きでも作者の承認を得てから出す（F18） |
| サイトを作る道具 | Material for MkDocs で作る（9.8 系に固定）。Zensical の試験ビルドを CI で並走させ、Material の保守が終わる 2027-05-05 までに移る。どちらでも動く書き方（MkDocs の hooks・macros・自作プラグインを使わず、生成は独立スクリプト）に限る | ユーザーの選択。2026-11-03 に確かめた事実：Material の最新は 9.8.0（2026-10-24。主にセキュリティの修正で、Python 3.11 以上が必要）、Zensical の最新は 0.0.74（2026-10-30、alpha） |
| 雛形の動作確認 | Claude Code の雛形は、制作の環境（この WSL）で、使い捨てのフォルダに `claude -p` を走らせて確かめ、版・OS・日付を記録する。アプリ（Web・Desktop・Mobile）など制作の環境で試せないものは、必要なときに作者に手順を渡して試してもらい、検証ノートにする | ユーザーの選択。requirements §11 の最初の質問の「検証ノートを作るときの環境」の答えでもある。実際に動かす確認は作者のプランの使用量を使う |
| Claude 用の索引 | `llms.txt`（1ページ1行）だけを front matter から生成する。分野ごとの詳細索引は作らない | ユーザーの選択 |
